# Skill: 일정 설계 작업법

## 언제 트리거되는가
- 사용자가 "일정 짜줘", "시간표 만들어줘", "Day1/2/3 계획"을 요청할 때
- destination-scout이 후보지를 제시하고 사용자가 1곳을 선택했을 때
- itinerary-planner 에이전트가 호출되었을 때

## 절차

### 1. 입력 확인
- [ ] 확정 여행지
- [ ] 출발일/복귀일
- [ ] 부모님 체력 수준 (상/중/하)
- [ ] 자차 vs 대중교통
- [ ] 음식 선호/비선호

### 2. 하루 골격 잡기
각 Day는 아래 골격을 따른다.

```
아침 (08:00-09:00)  식사
오전 (09:30-11:30)  주요 활동 1
점심 (12:00-13:00)  식사
휴식 (13:00-14:00)  ← 반드시 포함, 식후 1시간
오후 (14:00-16:30)  주요 활동 2
저녁 (17:30-19:00)  식사
야간 (19:00-)       자유 / 휴식 (강한 일정 금지)
```

### 3. 강도 분배
- Day1: 이동 + 가벼운 일정
- Day2: 메인 일정 (가장 활동량 많음)
- Day3: 가벼운 일정 + 복귀

### 4. 예약 필요 항목 표시
일정 안에 `[예약필요]` 태그를 붙여 booking-coordinator가 추출하기 쉽게 한다.

## 산출물 형식

```
## 2박 3일 일정 — (장소명)

### Day 1 (출발일)
| 시간 | 활동 | 장소 | 소요 | 메모 |
|---|---|---|---|---|
| 09:00 | 출발 | (출발지) | - | 자차 |
| 12:00 | 점심 [예약필요] | (식당) | 1h | 부드러운 음식 |
| 13:00 | 휴식 | 숙소 체크인 | 1h | |
| ... | ... | ... | ... | ... |

### Day 2 (메인)
...

### Day 3 (복귀일)
...

## 한 줄 요약
Day1 이동·가볍게 / Day2 메인 / Day3 여유롭게 복귀
```

## 품질 체크
- [ ] 각 Day에 식후 휴식 1시간이 있는가
- [ ] 하루 주요 활동이 3개를 넘지 않는가
- [ ] Day2가 가장 강하고 Day1/3은 가벼운가
- [ ] 예약 필요 항목에 `[예약필요]` 태그가 있는가
- [ ] 야간에 강행군이 없는가
